# Project Instructions

## 1. General
- Read the existing code before making changes.
- Understand the project structure and current implementation.
- Prefer simple, readable, maintainable solutions.
- Do not rewrite unrelated code.

## 2. Coding
- Follow the existing coding style and naming conventions.
- Reuse existing functions and classes where appropriate.
- Avoid unnecessary dependencies.
- Do not introduce duplicated logic.
- Keep changes minimal and focused.
- Before apply new code which may be a major or important change, add for permission.

## 3. Safety
- Do not delete files or perform destructive operations without confirmation.
- Do not overwrite user changes.
- Never hardcode API keys, passwords, or other secrets.
- Do not modify unrelated files.

## 4. Workflow
- Before complex changes, provide a short implementation plan.
- For bug fixes, identify the root cause before editing.
- After editing, run relevant tests or build commands.
- If tests cannot be run, explain why.
- Report files changed and summarize the results.

## 5. Communication
- Explain important decisions clearly.
- Ask questions when requirements are ambiguous.
- Do not claim tests passed unless they were actually run.
